# AOP-NP-instances

## 1.算例生成

鉴于现有标准算例库无法直接适配本文研究的多重图场景，本文基于经典 VRP 基准构建了包含 43 组测试算例的专用数据集，分为小规模与大规模两类，另设 5 组独立算例用于LrMA的个体效能评估。所有算例均遵循“X”命名规范，其中 X 代表节点规模。

**data_S：**该数据集基于cvrp 基准算例中的Augerat等人（1995）所提出的VRP实例中包含站点数n=32-65个节点的小规模的算例。采取了以下设置来适用于本问题：(a)针对坐标求取欧几里得距离，然后生成距离矩阵，对矩阵施加（-0.1，0.1）的随机扰动构成非对称矩阵；（b）根据距离矩阵生成多重图中两条弧的分数与时间，时间优先弧（时间短、分数低）的分数与时间系数分别是0.1、0.1，分数优先弧的分数（reij1）与时间系数是0.3、0.2；(c)节点分数为随机生成，其中有30%的高分数站点，高分数站点的分数为100，低分数站点的分数为1，另外节点的游览时间统一设为0。

**data_L：**该数据集基于基于cvrp 基准算例中的Uchoa等人（2017）所提出的VRP实例，生成了包含101-701个节点的23个算例。数据的设计均同data_S。

**data_E：**该数据基于tsp95中的kroA100、kroB100、kroC100、kroD100、kroE100进行生成。为增大求解难度，防止算法快速收敛，故调整了两条弧的分数与时间的系数，时间优先弧（时间短、分数低）的分数与时间系数分别是0.12、0.32，分数优先弧的分数（reij1）与时间系数是0.35、0.78，并保留4位小数；同时将节点的游览时间调整为节点分数的1.6倍，节点分数依旧随机生成。

### 算例格式

第1行：数据集标题及骑行节点数量（n）说明；

第2至3行：总预算时间阈值（T）标签及其数值；

第4至5行：节点分数；

第6至7行：节点时间；

第8行至第9+n行：时间优先弧的标签与分数矩阵；

第10+n至第11+2n行：分数优先弧的标签与分数矩阵；

第12+2n行至第13+3n行：时间优先弧的标签与时间矩阵；

第14+3n行至第15+4n行：分数优先弧的标签与时间矩阵

### 原始数据：

data_S 与 data_L 分别见 https://galgos.inf.puc-rio.br/cvrplib/index.php/en/instances 中的 Set A (Augerat et al., 1995) 与Set X (Uchoa et al., 2017)

data_E 见 https://github.com/shredderzwj/TSPLIB?tab=readme-ov-file 中的 kroA100、kroB100、kroC100、kroD100、kroE100 

## 2. LrEA 算法执行机制详解：以“变异算子”演化为例

为了帮助研究者深入理解 LrEA（基于大语言模型的反思型进化算法）的底层运行机制，本指南提供了一个**完全可复现、端到端**的具体示例。

在本示例中，我们将追踪 **LrEA 是如何从零开始，一步步自动优化求解 AONP（带节点收益的弧定向问题）的“变异算子 (Mutation Operator)”的**。本内容是对论文第三部分的具体实例化展示。

---

### 1. 初始环境与种子算子 (Phase 1: Initialization)

**任务**：演化出一个能跳出局部最优且不违反 AONP 严格时间约束的变异算子。
**种子算子 ($S_{mut}$)**：基础的 “两点交换 (Two-Point Swap)”。

最初的简单进化框架底座 ($LrEA\text{-}EA$) 搭载了这个种子变异算子：

```python
def mutation_v1(route, max_time, time_matrix):
    # 基础逻辑：随机选取两个非首尾节点进行互换
    idx1, idx2 = sorted(random.sample(range(1, len(route) - 1), 2))
    route[idx1], route[idx2] = route[idx2], route[idx1] 
    return route
```

**初始适应度**：$2500$ 

LrEA 首先会以角色扮演（虚拟算法专家）要求 LLM 对种子进行初期变异生成初始种群 ($P$)，并将它们的评估结果记录进 **“经验树 (Experience Tree)”**。

---

### 2. 经验树双分区状态 (Experience Tree Snapshot)

在进行几轮基础运行后，某算子槽位（变异算子）的经验树积累了以下数据。LrEA 独创的双分区架构将它们分为：

#### 🟢 成功分区 (T.succ)

记录了所有运行成功、没有报错的代码，并按适应度评分排列。

| 标识     | 适应度 (fitness) | 核心机制                                     | 状态记录             |
| -------- | ---------------- | -------------------------------------------- | -------------------- |
| `Mut_S1` | **2850** (最优)  | **块反转 (Block Reverse)**：反转子路径       | iter=2, pop_valid=12 |
| `Mut_S2` | 2710 (次优)      | **贪心插入**：移除低分节点，插入周边高分节点 | iter=1, pop_valid=8  |

#### 🔴 失败分区 (T.fail)

按引发崩溃的错误类别归档，用于提取避坑指南。

| 错误类型 (Err_Type) | 发生频次          | 代表性崩溃代码片段                                      | 崩溃原因分析                                     |
| ------------------- | ----------------- | ------------------------------------------------------- | ------------------------------------------------ |
| `Timeout` (超时)    | **3 次** (最高频) | `while calc_time(route) < max_time: insert_random(...)` | 死循环。新增节点时间过长致使退出条件永远无法满足 |
| `Constraint` (约束) | 2 次              | `route[0], route[-1] = route[-1], route[0]`             | 首尾节点被置换，导致起点和终点限制被破坏         |

---

### 3. 进化知识反思阶段 (Evolutionary Reflection)

进入下一代循环，LrEA 首先启动 **反思机制** (§3.4)。 
算法从上面的经验树中提取：

1. 最优的两个成功案例（`Mut_S1`, `Mut_S2`）
2. 频次最高的失败案例（`Timeout` 类型的死循环代码）

并将它们输入给 LLM 进行对比诊断，LLM 输出结构化反思指令 `R_doc`：

> **💡 LLM 反思诊断书 (Reflection Guidance):**
>
> 1. *成功经验提取*：优秀的算子普遍放弃了单纯的随机替换，而是（如 S1）注重保持现有路径的局部连续性，或（如 S2）融入了贪心收益考量。
> 2. *失败原因规避*：必须警惕随机插入导致的严重超时 (`Timeout`)。**切忌**使用 `while` 循环来逼近时间上限，应改用步数限制的 `for` 循环或单步增量验证机制。

---

### 4. 四类元进化算子分配与代码生成 (Meta-Evolutionary Generation)

假设我们单代允许生成的个体数 $M = 9$。根据余数轮询分配公式 ($B=\lfloor9/4\rfloor=2, R=1$)：

- **O1 结构重构** 获取 $2+1 = 3$ 个配额，**O2, O3, O4** 各获取 $2$ 个配额。

以下展示各类元算子如何在 反思指令（`R_doc`） 的加持下产生不同的迭代代码：

##### 🛠️ O1-结构重构 (Structural Explorer)

**目标**：打破常规，完全重构。
**LLM 规划 (Plan)**：放弃节点交换，采用破坏-重建（Ruin & Recreate）架构。随机移除 20% 节点（破坏），然后再使用受限时间框架贪心重建。考虑到反思指令的警告，在重建时采用严格的 `for` 循环与边界判定来杜绝超时。

```python
# O1 生成代码：彻底改变算法范式
def mutation_O1(route, max_time, time_matrix, profit_dict):
    # 破坏阶段
    num_remove = int(len(route)*0.2)
    # ... 安全的贪心重建逻辑，规避 while ...
```

##### 🧬 O2-机制融合 (Mechanism Fusion)

**目标**：结合种群中最优、中位和末位个体的特色。
**LLM 规划 (Plan)**：结合 `Mut_S1` 的路径反转（最优）和某末位个体的随机扰动。

```python
# O2 生成代码：先反转一个子区间增强局部连续性，再在边界随机扰动一个节点
def mutation_O2(route, max_time, time_matrix):
    route = block_reverse(route) # 继承自精英
    route = boundary_random_swap(route) # 继承自末位（防早熟）
```

##### 🎛️ O3-参数调优 (Parameter Tuning)

**目标**：在最优算子的基础上微调数值参数。
**LLM 规划 (Plan)**：不对 `Mut_S1` 的块反转结构做大幅修改，仅将其调优参数：将反转长度占比系数从固定 0.5 调整为根据路径总长动态判定（例如 `0.1 * len` 到 `0.4 * len` 之间）。

##### 🧠 O4-自适应增强 (Adaptive Enhancer)

**目标**：添加运行时状态感知的控制流。
**LLM 规划 (Plan)**：令算子具备自我意识。如果当前时间预算已经很紧张，则执行安全的局部小扰动；如果剩余时间非常充裕，则执行大范围破坏。

```python
# O4 生成代码：引入自适应 if-else 判断
def mutation_O4(route, max_time, time_matrix):
    used_time = calc_time(route, time_matrix)
    time_ratio = used_time / max_time
    if time_ratio > 0.9:
        return safe_local_swap(route) # 预算紧张
    else:
        return aggressive_block_swap(route) # 预算宽裕
```

### 5. 即插即用与框架替换 (Plug-and-Play Assembly)

上述元算子生成的 9 个新代码组件，将逐一被封装，并**临时即插即用**到 LrEA-EA 的宿主框架中（替换掉框架中旧的变异算子）进行测试评估。

最终评估结果显示，融合了自适应机制的 `O4 子代` 平均目标函数值突破到了 **3200** 并且运行稳定。

**槽位固化**：当“变异算子”槽位达到了最大演化代数限制时，这个 3200 分的超级算子 $C_{mut}^*$ 就会被永远编入代码库中：

```text
LrEA_EA.ReplaceOperator(slot="Mutation", C*_mut)
```

自此之后，LrEA 继续移动至下一个算子槽位（例如“局部搜索算子”或“弧选择算子”）进行一样的流程，**但这之后的搜寻，全都会自动运行在已经搭载了这款顶级自适应变异算子的超级框架体系上了**。这就是 LrEA 多槽位循序渐进演化的全过程。
